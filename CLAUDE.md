# CLAUDE.md

Self-hosted fork of ッツ (ttu) Ebook Reader with integrated whispersync, served from the user's Unraid NAS.
The app works today. Every change must be intentional and must not break reading.

## Design docs (read before starting any work)

- `docs/design/design-doc.md`: the agreed design (v1), organized by system. Section 13 maps it to current code; section 14 lists risks.
- `docs/design/dependency-map.md`: work packages (WP1-WP19), their prerequisites and the agreed phase order.
- `docs/design/decisions.md`: the log of individual decisions and verified facts about the code and the NAS.

If code and docs disagree, or a task needs a decision the docs don't cover, STOP and ask. Do not guess or silently extend the design.

The only writer is the cleanup apply sidecar (`ttsu-cleanup-apply`), only through the running Calibre content server via `calibredb --with-library http://…`, and only for cleanup batches and the user's edits from the reader (decided by the user for the Phase 6 cleanup, 2026-11-13; the user's edits added with Calibre metadata editing, 2026-11-23).
- Preserve whispersync's match/re-match/reset semantics; do not "improve" them.
- Keep audio out of the replicator.
- The app is served over plain http (HTTPS deferred). Feature-detect every secure-context API (service worker, `navigator.storage` persist/estimate, Web Locks, `crypto.randomUUID`, Clipboard API) and degrade gracefully; it must switch on automatically when `isSecureContext` is true.
- If a component secretly depended on the removed sandbox/chrome.runtime, STOP and report.
- Execute one phase (and one work package) at a time; honor each stop condition.
- Keep the browser tab title format `<book title> | ッツ Ebook Reader` (`lib/functions/format-page-title.ts`). Yomitan copies it into the user's Anki Comment field.
- Stats and tracking code must never block or break reading: isolate it and catch its errors.

- Work on a branch per work package; never commit directly to the main branch. Commits follow Conventional Commits (commitlint is configured).

## Playwright / Windows lockout

- In e2e scripts, never import `chromium` from `playwright-core` (nor `node_modules/playwright-core/index.mjs`). Import it from `C:\Data\Projects\local-ttsu\.tmp-e2e\scripts\lib\pw.mjs` (relative path from the script; `require` it with `createRequire` in CommonJS). Its `chromium.launch()` and `browser.newContext()`/`newPage()`/`close()`/`version()` work as before.
- Why: Chrome and Edge on Windows check once per profile whether the Windows password is blank by calling `LogonUser(<you>, ".", "", LOGON32_LOGON_INTERACTIVE, …)` (`chrome/browser/password_manager/password_manager_util_win.cc`, `CheckBlankPasswordWithPrefs`). At startup, every new tab's `ChromeAutofillClient` constructor reaches that check (`SupportsDeviceReauth` → `CanAuthenticateWithBiometricOrScreenLock` → `CanAuthenticateWithScreenLock`, behind `AutofillAiWalletPrivatePasses`/`AutofillAmbientAutofill`, on by default). The answer is cached only in the profile's `Local State` (`password_manager.os_password_blank`, `os_password_last_changed`). Playwright's plain `chromium.launch()` makes a new temp profile every time, so every launch is one failed logon (Event 4625, type 2, 0xC000006A), and 10 launches within 10 minutes lock the user's Windows account. Proven with the Security log on 2026-11-20 (`.tmp-e2e/lockout/results.jsonl`).
- How `pw.mjs` avoids it: each context is a persistent context on a new empty dir under `.tmp-e2e/pw-profiles/` (deleted on close, so no cookies, IndexedDB or localStorage carry over between contexts or runs, and parallel runs are safe), seeded with only the `password_manager` block of `Local State` that Chrome itself wrote on this PC (`pw-profiles/seed/`, refreshed after every run).
- Never point e2e scripts at a fresh `--user-data-dir` or a new `launchPersistentContext` dir without that seed. To check a change, run `.tmp-e2e/lockout/export-events.ps1` in an admin PowerShell and read failures with `node .tmp-e2e/scripts/lockout-count.mjs <since ISO time>`. `lockout-repro.mjs` deliberately imports `playwright-core` directly to reproduce the problem: run it only through its lockout governor.
